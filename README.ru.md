# Карта открытых ответов опроса

Два инструмента для кодировки открытых ответов. Данные никуда не отправляются: всё считается локально.

1. **Карта автотегов по сегментам** (`map/`) — ответы сами разбиваются на теги и подтеги так, чтобы теги как можно сильнее различались по сегментам. Результат — одна HTML-страница с приближением, подсветкой сегментов и фильтром «совпали с сегментом».
2. **Карта слов** (`app.R`, Shiny) — исследователь выделяет группу слов лассо, задаёт название и порог, и близкие по смыслу ответы получают тег. Результат — CSV рядом с базой.

В репозитории только код. Данные и результаты содержат ответы респондентов, поэтому `.gitignore` их исключает: не коммитьте `data/` и `map/out/`.

## Если у вас есть Claude Code

Откройте его в этой папке и напишите:

> Разберись по README и CLAUDE.md. База лежит в <ПУТЬ>.sav, открытый вопрос — <ПЕРЕМЕННАЯ>, сегменты — <ПЕРЕМЕННАЯ>. Пропиши это в настройках, посчитай пайплайн и карту автотегов, дай тегам и подтегам названия по map/out/summary.txt и покажи страницу на локальном сервере.

## Установка

Нужны R 4.3+ (на Windows ещё Rtools) и Python 3.

```
Rscript install_packages.R
pip install sentence-transformers pandas
```

Модель эмбеддингов (около 1 ГБ) скачается при первом запуске, модель лемматизации (около 44 МБ) — тоже, для этого нужен интернет. Сами ответы остаются на вашем компьютере.

## Настройка

В `pipeline/00_config.R` укажите:

- `RAW_SAV_PATH` — путь к базе .sav;
- `TEXT_VAR` — переменная с открытым вопросом;
- `SEGMENT_VAR` — переменная сегмента: число, текст или подписанная переменная SPSS;
- `MAP_K_FINE`, `MAP_K_MID`, `MAP_K_TOP` — сколько мелких скоплений, подтегов и тегов. Значения 120 / 36 / 12 подбирались на базе примерно в 3500 ответов; на базе заметно меньше их стоит уменьшить.

Лемматизатор настроен на русский язык.

## Карта автотегов

Все команды — из корня проекта.

```
Rscript run_pipeline.R        # база -> леммы -> векторы (несколько минут)
Rscript map/01_cluster.R      # разбивка на теги, печатает показатели качества
Rscript map/02_export.R       # раскладки карты, data.json и summary.txt
python map/build.py           # собирает map/out/map.html
python -m http.server 7950 --bind 127.0.0.1 --directory map/out
```

Страница: http://localhost:7950/map.html

**Названия тегов.** Без них подписи собираются из общих слов. Чтобы задать свои, посмотрите `map/out/summary.txt` и создайте `map/out/names.json` (порядок — как номера TOP и MID в сводке), затем повторите `02_export.R` и `build.py`:

```json
{"top": ["Название тега 1", "Название тега 2"], "mid": ["Название подтега 1"]}
```

После повторного запуска `01_cluster.R` с другими настройками или на других данных номера скоплений меняются, и названия нужно задавать заново.

### Как устроена разбивка

1. Ответы делятся на мелкие смысловые скопления (k-means по векторам).
2. Скопления склеиваются снизу вверх в подтеги и теги. Склеивать можно только соседей по смыслу, а из них выбирается пара с наименьшим штрафом: смысловое расстояние + `MAP_LAMBDA` × потеря информации о сегменте.
3. Первая раскладка карты — t-SNE по векторам с добавкой принадлежности к подтегам и тегам. Вторая — t-SNE по близости к каждому сегменту (косинус к центроиду сегмента, свой сегмент считается без самого ответа).

### Как читать результат

`01_cluster.R` печатает показатели, они же есть в шапке страницы:

- `V_seg` — связь тегов с сегментами (V Крамера);
- `V_base` — то же у обычной кластеризации на столько же групп, сравнивать надо с ней;
- `V_perm` — то же при случайной разбивке;
- `acc` и `majority` — как часто сегмент угадывается по тексту и какую долю базы занимает самый крупный сегмент. Если они близки, текст почти не говорит о сегменте, и большого `V_seg` ждать нельзя.

Ограничения:

- В первой раскладке теги разделены чётче, чем на чистой карте смыслов: она построена с учётом самих тегов. Расстояния между тегами отчасти условны, и разделение на карте не доказывает качество тегов.
- «Совпал с сегментом» значит, что ответ из сегмента, где тег встречается в 1,3 раза чаще среднего и больше. Таких сегментов у тега может быть несколько, поэтому это не доля угаданных сегментов.
- Разбивка подбирается под те же сегменты, по которым потом оценивается, поэтому показатель слегка завышен. Названия и состав тегов проверяйте глазами.

## Карта слов (Shiny)

```
Rscript run_pipeline.R
Rscript run_app.R
```

1. Каждое слово на карте — точка с подписью, размер шрифта = частота. Наведение показывает характерные ответы, клик — все ответы со словом.
2. Лассо выделяет группу близких слов. Слева задайте название тега и порог, предпросмотр покажет, сколько ответов попадёт в тег.
3. В таблице тегов можно посмотреть ответы, исключить слово или удалить тег.
4. «Перестроить по тегам» пересобирает карту по близости слов к тегам.
5. Итог для анализа — `data/base_with_tags.csv`.

## Источник векторов

Переключатель `EMBEDDING_SOURCE` в `pipeline/00_config.R`:

- `"llm"` (по умолчанию) — локальная модель `paraphrase-multilingual-mpnet-base-v2`; ответ кодируется целиком, рабочие пороги тегов примерно 0.4–0.7;
- `"word2vec"` — без Python, векторы обучаются на самом корпусе; пороги примерно 0.8–0.95.

После смены источника пересчитайте пайплайн и пересоздайте теги: пороги в разных пространствах несопоставимы.

## Структура

```
app.R, run_app.R         Shiny-приложение
run_pipeline.R           полный прогон пайплайна
install_packages.R       установка R-пакетов
pipeline/
  00_config.R            все настройки
  01_load_data.R         чтение .sav
  02_preprocess.R        очистка и лемматизация (udpipe)
  03_train_word2vec.R    векторы word2vec
  03b_embed_llm.R        LLM-эмбеддинги (через embed_local.py)
  04_prepare_app_data.R  t-SNE слов и данные для приложения
map/
  01_cluster.R           разбивка на теги под сегменты
  02_export.R            раскладки, data.json, summary.txt
  template.html          страница карты
  build.py               сборка map/out/map.html
data/, map/out/          создаются при работе, в репозиторий не попадают
```
